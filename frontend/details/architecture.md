# 桌面前端架构

## 定位

`frontend` 是桌面管理和运维端. `app` 是移动管理和运维端.

两个客户端功能一致, 使用相同的后端接口, 权限和业务状态. 差异只体现在操作流程, 页面布局和信息密度, 不为移动端另建一套业务规则.

## 技术栈

- Vue 3.
- TypeScript 严格模式.
- Vite.
- Vue Router.
- Pinia.
- Element Plus.
- Axios.
- 高德地图 JS API 2.0.
- Vitest.

ECharts 在报表模块开始开发时再引入. 当前不引入微前端, SSR, GraphQL, Tailwind 和额外请求缓存框架.

## 编码方式

- 统一使用 Composition API.
- 单文件组件使用 `<script setup lang="ts">`.
- 接口请求和响应必须声明 TypeScript 类型.
- 页面只组合业务组件, 不直接散落重复请求逻辑.
- Pinia 只保存跨页面状态, 不复制全部接口数据.
- 通用组件只在出现真实复用后提取.

## 工程结构

```text
frontend/
  details/
  src/
    api/
    components/
    layouts/
    router/
    stores/
    types/
    utils/
    views/
```

各页面按业务名称放在 `views` 中. 当前模块数量较少, 不提前增加多层领域目录.

## 当前实现

已创建 Vue 3 工程并完成车辆监控地图, 车辆资产列表, 车辆详情抽屉和历史轨迹回放. 页面直接调用后端现有接口, 支持北京和上海切换, 状态筛选, 分页, 请求取消, 加载, 空数据和错误状态.

地图和轨迹接口当前请求 GCJ-02, 后端统一从 WGS84 转换. 本地开发 Key 保存在 Git 忽略的环境文件中, 车辆分布和历史轨迹均使用高德 JS API 2.0; 未配置或加载失败时降级为坐标预览.

登录和 RBAC 尚未实现, 页面当前标识为开发环境. 后端会话接口完成前不实现伪登录.

根目录 Compose 已包含无状态前端容器. Nginx 在 `8081` 端口提供页面, 并同源代理后端接口.

## API 和状态

- Axios 实例统一设置 `/api` 前缀.
- 统一处理超时, 取消请求和业务错误.
- 页面离开或查询条件变化时取消过期请求.
- 日期时间按 ISO 8601 与后端交互.
- 城市和行政区使用标准代码, 显示名称由字典映射.
- 地图接口请求 GCJ-02 展示坐标, 原始轨迹仍由后端保存为 WGS84.

当前后端尚未提供登录和权限接口. GCJ-02 返回接口已完成; 生产高德 Key, 安全密钥, 域名白名单和同源安全代理仍待生产环境配置.

## 登录和权限

- 使用同域 HttpOnly Cookie.
- 会话状态保存在 Redis.
- 前端不把长期凭证写入 `localStorage`.
- 路由守卫只负责界面访问控制, 后端仍必须校验每个业务权限.
- 有写操作后增加 CSRF 防护.

建议的基础接口:

- `POST /api/v1/auth/login`.
- `POST /api/v1/auth/logout`.
- `GET /api/v1/auth/me`.

## 部署

- 开发环境使用 Vite dev server.
- Docker Compose 使用 Nginx 提供静态文件.
- Nginx 将 `/api` 代理到后端, 保持同域访问.
- 高德安全密钥通过 Nginx `_AMapService` 代理.
- 前端容器不保存业务状态, 可以直接替换和扩容.

## 质量要求

- 纯函数和关键交互逻辑使用 Vitest.
- 地图, 车辆详情和轨迹回放使用 Playwright 做桌面视口冒烟测试.
- 发布前检查加载失败, 空数据, 接口错误和无权限状态.
- 不以 mock 正常页面代替错误和空状态验证.
