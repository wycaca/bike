# 移动 App 架构

## 定位

`app` 是移动管理和运维端, 不是当前阶段的用户骑行 App.

`app` 与桌面端 `frontend` 功能一致, 使用相同的后端 API, 权限和业务状态. 移动端针对触摸操作, 小屏幕和现场作业重新组织页面, 不复制后端业务逻辑.

登录响应包含当前账号的数据范围. 移动端不自行拼接组织过滤条件, 车辆和任务列表直接使用后端返回的授权数据.

## 技术栈

- H5 使用 Vue 3 + TypeScript + Vite.
- 组件库使用 Vant.
- 路由使用 Vue Router.
- 全局状态使用 Pinia.
- HTTP 请求使用 Axios.
- 地图使用高德地图 JS API 2.0.
- Android 使用 Kotlin WebView 壳.

App 不复用 Element Plus 组件, 但接口类型, 状态枚举和业务术语必须与桌面端一致.

## 功能范围

与桌面端保持一致:

- 登录和权限.
- 车辆地图.
- 车辆检索和详情.
- 历史轨迹.
- 电子围栏和停车点.
- 告警处理.
- 换电, 维修和调度工单.
- 运营数据和审计记录.

移动端优先优化现场运维流程, 但不将桌面管理功能定义为不可用. 高密度表格在移动端改为列表, 摘要和逐层查看.

## 角色工作台

- `ADMIN` 管理人员使用运营总览、车辆、任务管理、作业管控和个人中心。
- `OPERATOR` 运维人员使用任务池、我的作业、作业路线、车辆和个人中心。
- 登录成功后根据后端返回角色进入对应首页，路由守卫禁止跨角色访问。
- 管理员负责派单、验收、异常处理、自动规则和批量任务；运维人员负责抢单、执行、凭证和现场异常。

## WebView 壳职责

原生壳只提供 H5 无法稳定完成的能力:

- 定位授权和当前位置.
- 扫码.
- 相机和照片选择.
- 文件上传辅助.
- 网络状态.
- 推送通知.
- 版本和设备信息.
- H5 首页加载失败时的原生错误提示和重新连接.

业务页面和业务规则保留在 H5 中.

## JSBridge

- Bridge 方法使用明确的版本号和参数结构.
- H5 只能调用白名单能力.
- 原生层校验调用来源和参数.
- 权限拒绝, 用户取消和系统失败必须返回可区分的错误码.
- 敏感操作不能只依赖前端按钮权限.

当前已实现定位、扫码和拍照/相册能力。支付、用户开锁和骑行控制不加入 Bridge。

移动地图 SDK 加载设置 8 秒超时并自动重试 1 次. 仍失败时清除失败缓存, 网络恢复后可以重新加载, 不要求用户退出 App.

## 服务连接错误

Android 原生层负责拦截 H5 主页面的加载失败, 避免显示 WebView 默认的“网页无法打开”页面. 当前区分以下错误:

- 设备未连接网络.
- 域名解析、连接拒绝或连接超时.
- 移动端页面不存在.
- 服务端 HTTP 5xx 异常.
- HTTPS 证书校验失败.

错误页显示中文处理建议、稳定故障代码和重新连接按钮. 仅主页面错误显示全屏提示, 高德地图等子资源失败仍由对应 H5 组件自行降级. 证书错误必须终止连接, 不允许用户忽略证书继续访问.

## 登录和安全

- App 只加载配置的 HTTPS 域名.
- 禁止任意外链获得 JSBridge 权限.
- WebView 关闭不需要的文件访问和调试能力.
- 登录使用与桌面端一致的后端会话和权限规则.
- 长期凭证不写入普通 H5 `localStorage`.
- 退出登录时同时清理 WebView Cookie 和后端 Redis 会话.

## 发布方式

- Android 壳和 H5 版本分别记录.
- H5 默认从受控 HTTPS 地址加载, 便于快速修复业务页面.
- 原生 Bridge 变更必须保持向后兼容或提高协议版本.
- 是否需要弱网离线处理, 需要在试点现场测试后确认.
