# 数据权限范围

## 目标

数据权限用于限制用户可读取和操作的组织数据, 与角色权限分开处理:

- 角色决定用户能否访问某类功能.
- 数据范围决定用户在该功能内能看到哪些组织的数据.
- 前端只负责展示和配置, 最终校验始终在后端完成.

## 范围模型

`app_user.data_scope` 支持三种值:

| 值 | 含义 |
| --- | --- |
| `ALL` | 全部组织数据. |
| `ORG_AND_CHILDREN` | 当前组织及递归下级组织. |
| `ORG_ONLY` | 仅当前组织. |

角色只提供默认值: `ADMIN` 默认 `ALL`, `AUDITOR` 默认 `ORG_AND_CHILDREN`, `OPERATOR` 默认 `ORG_ONLY`. 全量管理员可在用户管理页面调整具体账号的数据范围.

组织和用户管理属于全局配置, 仅 `ADMIN + ALL` 可以访问, 避免受限管理员通过修改账号扩大自身权限. 运维人员对任务的领取、执行和凭证操作除组织范围外, 仍必须满足“本人领取”的约束.

## 数据归属

- 车辆通过 `vehicle.org_id` 归属运营组织.
- 围栏、停车点、运维任务、自动规则和审计日志使用已有 `org_id`.
- Mock 北京车辆归属 `ORG-BJ`, 上海车辆归属 `ORG-SH`.
- Flyway V7 按车辆运营城市回填区域组织. 无法匹配组织时迁移中止, 不允许产生无归属车辆.

## 生效范围

以下查询统一应用组织范围:

- 车辆分页、详情、地图点和历史轨迹.
- 运营看板、车辆 CSV、收入报表和异步导出.
- 围栏、停车点、停车计数和空间违规.
- 运维任务、汇总、可指派人员、路线、附件和自动规则.
- 审计日志.

直接按编号访问越权资源时返回 HTTP 404 或 403, 且不返回资源内容. 新建、更新、停用、指派、路线规划和附件下载等操作在写入或读取文件前再次校验目标组织.

## 实现方式

`DataPermissionService` 根据登录主体解析组织编号集合. `ORG_AND_CHILDREN` 使用递归 CTE 查询组织树, SQL Mapper 通过参数化 `IN` 条件过滤. 当前不启用 PostgreSQL RLS, 因为应用仍是单一后端入口; 如果后续出现多个直连数据库的业务服务, 再评估数据库级隔离.

异步报表在创建任务时保存申请组织和申请时的数据范围. Worker 使用该快照生成文件, 不因用户后续退出或 Worker 无登录会话而绕过权限.

## 验证结果

2026-08-11 已完成以下验证:

- Docker 镜像内 `mvn -B verify` 通过 38 个测试.
- Flyway V7 成功应用, 北京和上海车辆各回填 100 辆.
- 北京 `ORG_ONLY` 运维账号在车辆、地图、看板、收入、地理设施、任务和规则接口均看不到上海数据.
- 越权访问上海车辆详情返回 HTTP 404.
- 北京 `ORG_AND_CHILDREN` 审计账号只返回 `ORG-BJ` 日志.
