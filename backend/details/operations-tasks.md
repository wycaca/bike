# 运维任务设计

## 设计依据

本模块仅参考中国大陆平台与地图服务的公开资料。平台功能调研见根目录的[中国大陆共享两轮车平台功能市场调研报告](../../中国大陆共享两轮车平台功能市场调研报告.md)。道路距离和驾车路线使用[高德开放平台路径规划 API](https://lbs.amap.com/api/webservice/guide/api/direction)，坐标在调用前由平台持久化的 WGS84 转为高德使用的 GCJ02。

公开资料无法确认各平台是否开放“运维人员抢单”的具体规则，因此任务分配按已确认业务规则实现：管理员可以直接派单，未指派任务进入城市公共任务池，由符合城市范围的运维人员抢单。

## 功能范围

任务覆盖换电、调度、维修、巡检、回收和清洁，支持以下闭环：

1. 遥测事件或管理员扫描触发规则，自动生成任务。
2. 同一车辆只保留一个活跃任务，新信号写入触发明细并增加聚合次数。
3. 管理员派单，或运维人员从公共任务池抢单。
4. 运维人员开始作业，上传现场照片并提交结构化完工凭证。
5. 管理员验收通过后完成任务；验收驳回则回到执行中。
6. 现场无法作业时上报异常，管理员选择重开任务或关闭任务。
7. 批量任务按车辆独立创建，单车冲突不会回滚整个批次。
8. 选中最多 16 个任务后，按高德驾车道路矩阵优化执行顺序。

## 自动规则与去重

| 触发类型 | 判断依据 | 默认任务 |
| --- | --- | --- |
| `LOW_BATTERY` | 电量低于规则阈值 | 换电 |
| `VEHICLE_FAULT` | 控制器故障或存在故障码 | 维修 |
| `VEHICLE_OFFLINE` | 车辆离线或控制器离线 | 巡检 |
| `GEO_VIOLATION` | 空闲车辆进入禁停区，或车辆离开运营区 | 回收 |

实时遥测只评估 30 分钟内的事件，避免 Kafka 历史重放产生过期任务。规则包含城市、执行组织、优先级、完成时限、冷却时间、标题模板和自动恢复开关。

去重分为三层：

1. 数据库部分唯一索引保证同一车辆只能有一个活跃任务。
2. 相同或不同规则再次触发时写入 `operations_task_trigger`，保留首次、最近时间和累计次数。
3. 已结束的规则任务在冷却时间内不重复创建，防止设备状态抖动反复派单。

规则条件恢复后，相应触发记录转为已恢复；规则生成且尚未开工的任务，在所有触发都恢复时可自动取消。

## 状态闭环

```text
OPEN -> CLAIMED -> IN_PROGRESS -> PENDING_REVIEW -> COMPLETED
  ^         |            |              |
  |---------|            |              +-- 驳回 -> IN_PROGRESS
      释放               +-- 上报异常 -> EXCEPTION
                                          |-- 重开 -> CLAIMED / IN_PROGRESS
                                          +-- 关闭 -> CANCELLED

任意未结束状态 -- 管理员取消 --> CANCELLED
```

抢单使用带状态条件的原子更新。后续流转同时检查状态、领取人和 `version` 乐观锁，冲突返回 `409`。每次成功操作都追加不可变事件，管理员可以查看任务由谁领取、谁提交、谁验收以及异常如何处理。

## 作业凭证

完工凭证包含处理结果、现场经纬度、检查项、处理前后照片，以及按任务类型要求的字段：

- 换电：换出电池编号、换入电池编号，两者不能相同。
- 调度：实际停放经纬度。
- 维修：使用物料列表。
- 所有任务：至少一张处理后照片，全部凭证先进入待验收状态。

照片仅支持 JPEG/PNG，单张上限 8 MB。服务验证真实图片内容，文件使用随机名称落盘，数据库记录 SHA-256、原始名称、用途、上传人和任务归属。下载使用文件流，避免大图片整体进入 JVM 堆。Compose 使用独立 `bike-ops-evidence-data` 卷；生产环境可将存储实现替换为中国大陆对象存储。

## 路线优化

路线服务先调用高德距离测量接口生成非对称驾车道路矩阵，再使用以下步骤排序：

1. 固定第一个任务或用户起点。
2. 最近邻算法生成初始顺序。
3. 2-opt 反转中间区间，直到路线不再缩短。
4. 使用优化顺序调用高德驾车路径规划，返回道路折线、分段距离和预计时长。

高德 Key 缺失或接口异常时返回 `LOCAL_ESTIMATE`，使用球面距离乘道路修正系数，并在响应中给出告警；估算结果不能用于里程结算。

## 接口

| 方法与路径 | 用途 |
| --- | --- |
| `GET/POST/PUT /api/v1/ops/rules` | 查询、新建、更新自动任务规则。 |
| `POST /api/v1/ops/automation/scan` | 管理员立即扫描城市车辆状态。 |
| `GET/POST /api/v1/ops/tasks` | 分页查询或创建单个任务。 |
| `POST /api/v1/ops/tasks/batch` | 批量创建任务并返回逐车结果。 |
| `POST /api/v1/ops/tasks/{id}/claim` | 运维人员抢单。 |
| `PUT /api/v1/ops/tasks/{id}/assignment` | 管理员指派或改派。 |
| `POST /api/v1/ops/tasks/{id}/release` | 领取人释放任务。 |
| `POST /api/v1/ops/tasks/{id}/start` | 领取人开始任务。 |
| `POST /api/v1/ops/tasks/{id}/attachments` | 上传处理前、处理后或异常照片。 |
| `POST /api/v1/ops/tasks/{id}/complete` | 提交结构化完工凭证。 |
| `POST /api/v1/ops/tasks/{id}/review` | 管理员验收或退回。 |
| `POST /api/v1/ops/tasks/{id}/exception` | 运维人员上报现场异常。 |
| `POST /api/v1/ops/tasks/{id}/exception/resolve` | 管理员重开或关闭异常任务。 |
| `POST /api/v1/ops/routes/optimize` | 优化最多 16 个任务的道路顺序。 |

## 尚未覆盖

配件库存扣减、人工工时与单任务成本、班次交接、消息推送、运维人员实时位置和按技能负载自动派单仍未实现。它们依赖库存、排班或移动端位置数据，应作为后续独立模块接入。
