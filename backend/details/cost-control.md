# 后端成本控制

各阶段机器规格和价格估算统一记录在根目录 `cost.md`. 本文只记录后端实现中的成本控制规则.

## 当前规则

- 保持模块化单体, 减少服务数量和运维资源.
- 后端实例无状态, 按实际请求量横向扩容.
- Redis 只保存最新状态和短期状态.
- Kafka 只做消息缓冲, 默认保留 1 到 3 天.
- 地图按当前视野查询, 低缩放级别返回聚合结果.
- 轨迹查询限制时间范围和点数.
- 报表后续读取聚合表, 不直接扫描轨迹明细.
- 文件和冷数据使用对象存储, 不长期占用数据库高性能磁盘.

## 车辆上报

- 骑行车辆使用较高定位频率.
- 静止车辆降低上报频率.
- 告警事件不受普通位置降频影响.
- 最终频率以雅迪能力和北京, 上海监管要求为准.

降低无效上报可以同时减少 Kafka 流量, 数据库写入, 存储和备份成本.

## 轨迹存储

原始轨迹保留策略确认后再启用:

- TimescaleDB 压缩.
- 自动清理策略.
- 对象存储归档.
- 简化轨迹和小时聚合.

在业务确认前不提前删除原始轨迹, 也不承诺永久保存全部原始点.

## 扩容触发条件

只有监控数据证明存在瓶颈时才扩容或拆服务. 重点观察:

- API P95 和 P99 延迟.
- 数据库 CPU, 连接数和慢查询.
- Kafka consumer lag.
- Redis 内存和命中率.
- 每日轨迹写入量和磁盘增长.

优先进行索引, SQL, 批处理和采样频率优化. 这些措施无效后, 再增加机器或拆分 IoT 接入和消费进程.
