# 收入报表与指标口径

## 行业口径

“单车单日收入”不宜称为 ARPU。ARPU 的分母通常是用户，而单车是供给资产。本项目采用以下两个互补指标：

- **单车日均骑行次数（RpD）**：`有效订单数 / 投放车辆日数`，也称车辆周转率。Bird 在 SEC 年报中使用 `Rides per Deployed Vehicle per Day` 衡量车辆利用率；横琴共享单车管理办法也把车辆周转率定义为自然日有效订单数与投放车辆数之比。
- **单车日均收入（RevPVD）**：`净收入 / 投放车辆日数`。这是内部单位经济派生指标，可拆为 `RpD × 单均收入`，用于同时观察周转和变现能力。

行业资料也普遍同时观察骑行次数、投放规模、单次距离和单次时长。NABSA 的行业报告按 `trips / vehicle / service day` 比较利用率，并同时报告平均骑行距离和时长。

## 已实现指标

| 指标 | 公式 | 用途 |
| --- | --- | --- |
| 总流水 | 完成骑行的订单原价合计 | 观察交易规模，不扣优惠和退款 |
| 净收入 | 总流水 - 优惠 - 退款 | 日/月经营收入主口径 |
| 有效订单 | 非取消订单数 | 包括已支付、部分退款和全额退款的真实骑行 |
| 活跃车辆 | 周期内产生有效订单的去重车辆数 | 观察真正参与运营的供给 |
| 平均投放车辆 | 投放车辆日数 / 周期自然日数 | 处理月中扩容和部分周期查询 |
| RpD | 有效订单 / 投放车辆日数 | 车辆利用率或周转率 |
| 单均收入 | 净收入 / 有效订单 | 每次骑行的净变现能力 |
| RevPVD | 净收入 / 投放车辆日数 | 每辆投放车辆每天的净收入 |
| 优惠率 | 优惠金额 / 总流水 | 促销对收入的影响 |
| 退款率 | 退款金额 /（总流水 - 优惠） | 实付口径的退款质量 |
| 平均时长/距离 | 有效订单时长、距离合计 / 有效订单 | 骑行结构和定价分析 |

报表按 `Asia/Shanghai` 自然日聚合，查询日期为闭区间，单次最多 366 天。CSV 使用 UTF-8 BOM，确保 Excel 直接打开中文不乱码。CSV 导出由独立 Worker 异步生成，设计与运维边界见 [异步报表 Worker](report-export-worker.md)。

## 数据与分母

投放车辆日数按每天满足以下条件的车辆求和：

1. 车辆所属城市与查询城市一致。
2. 投放日期不晚于统计日。
3. 当前生命周期为运营中或调度中；维护、退役、扣押和待投放车辆不进入分母。

Mock 环境使用固定随机种子生成最近 120 个完整自然日的订单，并尊重车辆资产的实际投放日期。因此当前样例车辆从 2026 年 7 月投放，收入从 7 月开始出现。

生产环境应增加“车辆投放状态历史”或小时级可用性快照。Bird 的口径会按 24 小时折算投放车辆，并排除充电、维修和暂时丢失车辆；仅用当前生命周期状态无法准确回溯长期历史。

## 后续指标

收入与周转只能说明规模和效率，完整经营分析还应逐步补齐：

- **贡献利润**：净收入减支付通道费、保险、调度、换电和维修等直接骑行成本。
- **折旧前/后骑行利润**：分别观察现金回报和车辆资产消耗；Bird 的公开口径也同时披露两者。
- **单车日均成本与回本周期**：日均直接成本、车辆采购成本和累计贡献利润结合。
- **可用率与停机原因**：可骑、充电、维修、丢失、扣押的车辆时长占比。
- **区域与时段效率**：按运营区、停车点、小时和工作日拆分订单、RpD、收入与缺车率。
- **用户质量**：付费骑行用户、复骑率、会员/单次骑行结构、获客成本和生命周期价值。
- **服务与治理**：规范停车率、围栏命中率、投诉率、故障响应和调度完成时长。

成本、折旧和用户增长目前没有可靠事实数据，因此本期不生成虚假的毛利、贡献利润或 LTV。

## 接口

```text
GET /api/v1/reports/revenue
POST /api/v1/reports/exports
GET /api/v1/reports/exports/{jobId}
GET /api/v1/reports/exports/{jobId}/file
```

交互式汇总接口的查询参数为 `cityCode`、`fromDate`、`toDate` 和 `granularity=DAY|MONTH`。日期省略时默认返回截至昨日的最近 30 个完整自然日。

异步导出请求体包含 `reportType=REVENUE` 以及相同的城市、日期和粒度参数。创建接口返回 `202 Accepted` 和 `PENDING` 任务；前端轮询任务状态，仅在 `SUCCEEDED` 后调用文件接口。单用户最多同时保留 3 个等待或执行中的任务。
